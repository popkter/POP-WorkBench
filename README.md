# 泡泡的工作台 · Pop’s Workbench

泡泡的工作台（Pop’s Workbench，原泡泡工具箱）1.1.3 是一款 Windows/macOS 桌面工作台，用于集中管理内置能力、个人脚本、Android 设备和交互式终端。

应用数据默认保存在本机。自定义脚本、参数和执行输出不会作为工具内容上传；Jira 飞书推送、PowerShell 7 插件安装、Python 依赖安装和应用更新会在用户使用对应功能时访问相关服务。

> 本文适用于当前 1.1.3 源码版本；已安装版本的功能以对应发布版本为准。

Windows 推荐下载**完整版 `PopTools-Setup.exe`**：预置 Python、Android 工具（ADB + scrcpy）和 PowerShell，安装后即可使用。纯净版 `PopTools-Clean-Setup.exe` 不附带这三套运行时，可按需安装插件或指定本地环境。

项目围绕脚本管理与参数化执行，集成 Android 设备调试、投屏录制、终端与日常工具。

为保持已有安装、本地数据与自动更新兼容，内部 Python 模块名 `poptools`、`PopTools` 数据目录、更新资产文件名和 Windows 程序文件名 `泡泡工具箱.exe` 保持不变。新命令入口为 `pops-workbench`，原 `poptools` 命令仍可使用。

## 主要功能

- **自定义脚本**：在双栏工作区中创建、编辑、删除、搜索、筛选和运行 PowerShell、Bash、Batch、Python 脚本。
- **运行参数**：从脚本占位符自动生成文本、多行、数字、复选框、下拉、单选、文件、目录或密码控件；文本框（含密码）支持保存默认值。
- **脚本迁移**：通过剪贴板分享或导入单个脚本，也可通过目录批量导入、导出全部本地脚本。
- **预设功能**：提供设备投屏、画面/音频/logcat 联合录制、视频预览与逐帧查看、调色盘。
- **Android 设备**：自动扫描设备，全局选择并记住目标设备，脚本、投屏和录屏共享同一选择。
- **Python 环境**：应用维护独立 Python 运行时和虚拟环境，并通过 Python Doctor 异步检查、准备和安装脚本依赖；安装支持取消和超时处理。
- **内置终端**：可选 PowerShell 7 或 macOS Shell，支持多个独立会话，共用应用的 ADB 与 Python 环境。
- **外观设置**：支持跟随系统、浅色和深色模式。
- **使用手册**：从“设置 → 关于 → 用户手册”打开原生弹窗，支持章节阅读、脚本模板复制和参数替换预览；随应用切换明暗主题，无需浏览器引擎。
- **应用更新**：支持每天、每周或关闭自动检查，可选择正式版或 Beta 渠道，并在应用内下载、校验和安装更新。
- **桌面集成**：单实例运行、系统托盘、预设工具与最近使用脚本快捷入口。

## 快速开始

1. 在 Windows 10/11 中运行安装版或便携版程序，或在 macOS 12 及以上版本解压并运行 `.app`。
2. 首次启动后阅读应用内引导。
   引导内嵌离线 HTML 手册，支持模板编辑、参数预览和结果复制。阅读后点击右上角“关闭”，
   后续启动不再自动显示；随时可从“设置 → 关于 → 用户帮助”重新打开。
3. 使用左侧“自定义”或“预设”进入对应页面。
4. 使用 Android 功能前，在设备上开启 USB 调试并授权电脑，然后在该功能的“目标设备”下拉框中选择设备。
5. 窗口关闭后应用会留在系统托盘；需要完全退出时使用托盘菜单中的“退出”。

## 界面入口

| 入口 | 用途 |
| --- | --- |
| 自定义 | 左侧搜索、筛选和选择脚本，右侧配置参数、运行、编辑、分享或删除 |
| 预设 | 使用设备投屏、联合录制、视频预览和调色盘 |
| 终端 | 打开多标签交互式 Shell；Windows 首次进入时按提示准备 PowerShell 7 |
| 设置 | 切换明暗模式，打开或迁移脚本目录，查看运行环境并管理应用更新 |

系统托盘提供预设工具和最近使用自定义脚本的快捷入口。有参数或使用 Android 设备的脚本会先显示配置窗口，其他无参数脚本直接运行。

应用处于后台时，屏幕右侧会显示悬浮入口。点击头像向左展开全部脚本，可搜索、筛选、排序并快捷运行。未置顶时，鼠标离开且未操作脚本弹窗 300 毫秒后收起列表；点击脚本打开弹窗不会主动收起列表。标题栏的置顶图标可让卡包在失去焦点后保持展开，也可按 Esc、收起图标或再次点击头像手动收起。拖动头像可调整并记住垂直位置；在“设置 → 后台悬浮入口”中可关闭此功能。

Windows 根据系统实际前台窗口决定悬浮入口是否显示，启动后无需先点击主界面。焦点通知缺失时每 250 毫秒补充核对；关闭悬浮入口、置顶或退出应用后停止这项核对。

所有主题均提供置顶和收回全部图标，按钮及脚本项不显示悬浮提示。收回全部在 Decade 主题下让已打开卡牌约每隔 100 毫秒紧接着飞回卡包，多张卡的回收动画重叠，形成连续收卡效果，连续点击不会重复排队；在其他主题下关闭全部自定义脚本弹窗。入场中的卡牌也可收回，正在运行的脚本不会被停止。

操作脚本执行弹窗时，悬浮入口保持可用，可继续打开其他脚本的执行弹窗。每个脚本窗口独立保存当前参数、运行状态和控制台输出；再次打开同一脚本会激活原窗口，关闭窗口不停止其后台任务，运行仍遵循设置中的并发容量。

在“设置 → 外观与交互 → 主题模式”选择 **Decade**，启用黑灰底色、品红高亮和机械卡片动效；选择会保存并即时应用到已打开的窗口。浅色、深色及跟随系统主题使用 180 毫秒渐显、140 毫秒渐隐，重复点击已打开的卡片只激活窗口，不旋转或扫光。

Decade 主题下，悬浮脚本列表显示为左右对齐的层叠卡包，用上沿投影和厚度表现后一张卡压住前一张卡，露出的卡头可点击抽出。卡包、飞行和归还复用同一个卡面对象：点击后直接从队列中的原位置飞出，从首帧起始终渲染完整卡面，由卡叠左边缘和卡头下沿形成固定遮挡；先沿左上方向斜抽，再转向运行窗口，卡身随抽离逐渐露出，卡包外保持完整卡牌轮廓；不同卡牌各自播放动画，运行表单异步加载，连续点击不会同步构建整张表单而阻塞上一张；入场中重复点击同一卡牌不会截断飞行。若表单尚未准备好，仅该卡在落点保留卡面，准备完成后继续扫光。点击 X 后，卡面沿相同曲线反向插回左上出入口，真正进入卡包时才被队列遮住卡身、保留卡头，不按动画时间提前裁成横条，再以同一卡面归位，避免卡身从卡包底部露出；途中不插入空白占位。Decade 卡包高度为 360 逻辑像素，并受屏幕可用高度限制，其他主题仍为 480；最后一张卡的完整高度计入滚动范围，滚到底仍可查看卡面。回收完成时先隐藏旧窗口再清理遮罩，禁用系统矩形阴影以避免归位后残影。卡牌弹窗不再显示最小化按钮。所有卡牌（包括无参数脚本）均先打开运行卡片，再由用户点击运行。浅色、深色主题仍使用普通列表。

自定义脚本运行卡片统一按原设计的 5/7 显示（约 314 × 486 逻辑像素），文字、控件、间距与扫光同步缩放；Decade 卡包同步收窄并缩小叠放间距。出卡先保持队列中的尺寸向左上抽离，完整离开卡包后再转向目标窗口并放大到运行尺寸；底部行也使用同一抽离过程，收卡沿原路反向插回。

Decade 运行卡片使用黑底品红细边框、小圆角及居中的低对比菱形背景，菱形内部显示当前脚本配置的图标，未配置时使用终端图标。标题同行提供运行/停止、双镜头相机样式的设备选择和关闭按钮。机械次数模块读取真实累计使用次数，固定十个等大正方形格子；0–9 次每格 1 次，10–99 次每格 10 次，100–999 次每格 100 次，以此类推，只点亮完整格，数字显示准确次数。参数表单直接接在计数器下方，保留默认值保存、路径选择及回车运行。控制台默认收起，运行时自动展开，输出可选择复制、清空。卡包中展示的是卡背：亮色菱形与脚本图标居中并随卡背尺寸缩放，标题下有分割线；飞行和归还继续复用同一卡背对象。

Decade 卡包外壳采用碳黑底板、单层低对比外边缘和少量品红点缀。保留条码标题栏、卡背品红边框及薄层叠阴影；卡槽和数量栏不加框，工具按钮仅在悬停或置顶选中时显示底色，搜索框仅在聚焦时显示描边。装饰不接收输入，卡牌抽出、归还、滚动及收回队列继续使用原有位置计算和遮挡逻辑。

Decade 主题下，从卡包打开自定义脚本运行卡片时，实际运行窗口直接接住队列中的同一卡面，沿弧线等比放大到目标位置，落地后绕 Y 轴旋转一周（420 毫秒），再完成 300 毫秒的柔和品红扫光；飞行、旋转和扫光共约 1080 毫秒。第一张卡片落在屏幕可用区域左上角，边距 32 像素，后续卡片向右下方依次错开。飞出、扫描和内容展示使用同一个运行窗口、同一份表单。通过其他入口再次打开同一脚本时，复用原卡牌并绕 Y 轴旋转一周，再扫光一次；双击卡片标题栏也可触发旋转一周后扫光，拖动标题栏仍可移动窗口，动画中重复双击不会重启。卡包中不会显示已抽出的卡牌。点击 X 时，卡片收起内容并缩小飞回卡包当前排序中的位置，落地前减速，完成后关闭运行窗口。运行中的脚本也可点击查看卡片，不会重复启动。

Decade 主题下，点击位于后台的运行卡片，使它成为当前窗口时，仅播放一次 300 毫秒扫光作为激活反馈。扫光不拦截输入或按钮操作；点击已经激活的卡片不会反复播放，也不会与入场、列表旋转或回收动画叠加。

## 预设功能

预设页的“其他预设”提供以下四项功能，支持搜索名称或说明。

### Android 设备投屏

使用随应用提供并经过清单校验的 ADB 与 scrcpy，将当前所选 Android 设备画面嵌入主界面。投屏使用独立运行名额，切换到其他页面时隐藏原生投屏窗口，停止功能或退出应用时回收相关进程。

标题栏中的“屏幕”选择框支持查询当前设备的 displayId 列表，也可手动输入非负整数（默认 `0`）。投屏时，从下拉列表选择屏幕会立即重启投屏；手动输入后按 Enter 才切换。尚未投屏时只更新选择，点击“开始投屏”后使用。列表查询失败时仍可手动输入，刷新入口位于屏幕下拉菜单中。

### 记录日志与视频

同时录制 Android 设备画面、系统声音、麦克风，并将 logcat 保存为文本。开始录制前会清空设备 logcat 缓冲区；停止后选择保存目录，应用会生成日期时间命名的子目录并保存 `recording.mp4` 与 `logcat.txt`。

该功能需要 Android 11 或更高版本，设备还需支持 `VOICE_PERFORMANCE` 音源。部分应用可能禁止内部音频采集。

### 调色盘

支持输入和预览 `#RRGGBB`、`#AARRGGBB`，通过色相、饱和度、明度和透明度调整颜色，并可调用系统屏幕取色器获取颜色。

### 视频预览

通过标题栏的文件夹按钮或 `Ctrl+O` 打开本地视频，文件对话框支持按住 Ctrl/Shift 多选；也可拖入一个或多个 MP4、MOV、MKV、AVI、WebM、M4V、TS、MTS 文件。新文件追加到播放列表；首次打开停在第一帧，切换文件时保留各自的观看位置。标题栏“播放列表”显示视频数量；添加文件后列表中有多个视频时自动展开与主画面等高的右侧半透明抽屉，从画面右边滑出，不挤占主画面空间。点击列表项切换视频，可在抽屉内继续“添加视频”或移除条目；选择视频、点击外部或按 Esc 收起，随时可从标题栏重新打开。

播放、暂停、上一帧、下一帧、倍速和静音位于画面下方；空格播放/暂停，左右方向键逐帧查看。播放到结尾停留在最后一帧，不自动切换文件。视频解码统一使用 PyAV/FFmpeg，声音通过系统音频设备输出；当前倍速播放的声音音调随速度变化。Windows 暂停或拖动时立即丢弃旧声音，短时间恢复播放复用音频设备，空闲 15 秒后释放，减少反复定位时的设备打开开销。

主画面内滚动鼠标滚轮，以鼠标所在位置为中心缩放，最高放大到适应窗口时的 16 倍。放大后按住左键或中键拖动画面；边界自动限制，避免把画面拖出视野。画面下方显示缩放比例，点击“复位”恢复完整画面。播放、逐帧和时间轴定位保留当前缩放位置，切换视频自动复位；双击画面仍可播放/暂停。画面下方“适应画面／复位”旁的“截图”按钮会截取当前缩放、平移后的视频窗口可见区域（含留黑区域），不包含控制栏、时间轴和播放列表抽屉；图片复制到剪贴板后显示完成提示。

时间轴采用刻度尺、紧凑缩略图轨道和带抓手的竖直播放头，不显示帧数。点击轨道或拖动播放头时主画面持续跟随定位，拖动期间临时暂停；松手并完成精确定位后恢复操作前的播放状态，原本暂停则保持暂停。鼠标悬停时，在当前位置上方显示对应帧的浮动预览，拖动期间立即隐藏并停止悬停取帧，移开后隐藏，悬停本身不改变主画面，也不占用独立预览区域。时间轴右侧按钮或 `Ctrl+滚轮` 缩放，普通滚轮、中键拖动或下方滚动条浏览放大后的范围。时间轴右上角的“定位播放头”按钮保持缩放比例，将当前播放头滚动到视野中央（靠近视频首尾时按边界限制），不改变播放位置或播放状态。缩小时展示抽样画面，充分放大后展示连续源视频帧及其真实边界；可变帧率视频按显示时间戳定位。

播放、时间轴和悬停取帧在后台执行，快速移动时以最新请求为准。离开视频页面或隐藏主窗口会暂停播放。播放列表与位置保存在应用数据目录的 `video-preview.json`，移出列表不会删除源文件；移除后会取消相关后台读取并释放文件占用，可在文件管理器中移动或删除源文件。默认按视频原生分辨率输出主画面；画面下方可选择 720P、1080P、2K（1440）、4K（2160），只提供不超过源视频短边尺寸的档位，并保持宽高比。切换视频恢复原生画质。首帧显示后后台校正尾部时长，相邻向前定位复用解码进度。拖动时使用最长边不超过 960 像素的预览，首次解码的预览立即进入最多 48MB 的内存缓存；松手后恢复所选画质的精确画面。

高清短片会后台生成整段视频的磁盘预览，界面显示“正在优化拖动预览”。超过 5 分钟或文件达到 2GB 的素材改为按需生成当前位置前后约 4 秒的预览，避免整部电影从片头持续解码；先准备当前位置和后方画面，再补前方画面。已生成片段可立即使用，重开未修改的文件可复用。缓存按文件路径、大小和修改时间区分，每段视频的压缩画面最多 512MB，缓存目录按 2GB 总预算清理旧缓存；长片缓存达到上限后淘汰距离当前位置较远的片段。正常播放与松手后的精确定位始终使用源视频。MKV 等带视频索引的文件通过视频索引定位音频，再按音频时间戳裁剪到目标位置，减少大文件跳转后的声音等待。当前采用软件解码，首次准备时间和未缓存位置的响应取决于素材与设备性能。

### Jira 飞书推送

按 JQL 查询 Jira Issue，按负责人组织内容并生成飞书互动卡片。功能支持：

- 创建、复制、选择和删除多套推送方案；
- Jira 地址、Token/PAT、JQL 与最大结果数配置；
- 飞书机器人 Webhook、关键词和签名校验；
- 使用飞书 App ID、App Secret 与邮箱域名解析负责人 `open_id`；
- Jira 连接测试、消息预览、立即推送和运行日志；
- 按分钟间隔或每日多个时刻调度。

每个方案分别保存 Jira、飞书、消息和调度设置。定时调度仅在泡泡的工作台进程运行期间生效，窗口隐藏到托盘后仍会继续，完全退出应用后停止。

## 自定义脚本

### 创建与管理

1. 进入“自定义”。
2. 点击右上角“新建脚本”。
3. 填写名称、说明，选择图标和 `PowerShell`、`Bash`、`Batch 脚本` 或 `Python`。
4. 输入脚本内容并保存。
5. 在右侧详情区填写参数，然后点击“运行脚本”。

自定义页面采用脚本列表与详情区并排布局。列表可筛选 Batch、PowerShell 和 Python，并按添加时间、名称或使用频率排序；搜索会匹配脚本名称、说明和运行方式。详情区提供分享、编辑、删除、运行/停止以及可展开的控制台输出。

右侧“参数配置”区域支持文件和文件夹选择，文本输入框右侧的保存图标用于“设为默认值”。文件、文件夹参数框会并排显示保存和选择按钮。

同一个脚本不能重复启动。达到运行容量上限时，应用会提示是否停止最早启动的任务后运行新任务。

### 脚本中的 Android 设备

默认静态检测脚本中的 ADB 调用：支持直接命令、带引号的 ADB 路径、常见 Shell 调用和 Python 的 `subprocess` / `os.system` 调用。只读取直接引用的本地脚本，不执行脚本进行检测，也不追踪导入模块。动态拼接或第三方封装无法可靠识别时，在编辑器中将“Android 设备”改为“使用”；选“不使用”可关闭设备选择。

设备选择全局共享并保存，切换或删除脚本不会改变所选设备，分享脚本不会携带设备记录。自定义页面的设备选择器位于标题栏。首次只有一台可用设备时自动选择，多台时手动选择。当前设备仍在线时，新设备接入不会抢占选择；当前设备断开后有新设备接入时，自动替换为新接入的设备。也可展开下拉框刷新或手动选择，已提交的任务继续使用提交时的设备。

应用通过本次进程的 `ANDROID_SERIAL` 指定设备，不修改脚本。脚本中的 `adb -s`、`-d`、`-e`、`-t` 保持原样；界面选择仅作用于没有显式指定目标的调用。只有 `devices`、`version`、`help`、`start-server`、`kill-server`、`connect`、`disconnect` 等已识别的主机操作时，无须选择设备。已经提交或运行的任务保持提交时的设备。

### 用占位符生成参数控件

统一格式为 `${名称@类型:默认值}`，类型和默认值均可省略。新脚本推荐显式标注类型：

| 控件 | 模板示例 | 行为 |
| --- | --- | --- |
| 单行文本 | `${名称@text:示例}` | 省略类型时默认使用文本框 |
| 多行文本 | `${说明@multiline}` | 保留输入中的换行 |
| 整数 | `${重试次数@integer:3}` | 输入及运行前校验整数 |
| 数字 | `${比例@number:0.5}` | 支持整数、小数和科学计数法 |
| 复选框 | `${启用缓存@boolean:true}` | 输出 `true` / `false`；省略默认值时不勾选 |
| 下拉单选 | `${模式@choice:开启=1\|关闭=0}` | 显示标签，输出对应值；第一项为默认选项 |
| 单选按钮组 | `${环境@radio:开发=dev\|生产=prod}` | 显示标签，输出对应值；第一项为默认选项 |
| 文件 | `${输入文件@file:./input.txt}` | 输入路径或浏览选择文件 |
| 目录 | `${输出目录@dir:./output}` | 输入路径或浏览选择目录 |
| 密码 | `${访问令牌@secret}` | 隐藏输入；支持声明默认值和保存当前输入 |

显式 `@text` 的默认值始终作为文本处理，例如 `${内容@text:开启=1|关闭=0}` 不会创建下拉框。多行内容在输入框中填写，替换时保留换行；脚本需要按所用语言正确处理引号和转义。

旧脚本继续兼容 `${名称}`、`${名称:默认值}`、`${名称=默认值}`、`${标题:开启=1|关闭=0}`、`${开启=1|关闭=0}` 以及 `Var` / `pVal` 声明。下面的省略类型写法仍然有效：

使用 `${标题}` 创建空文本输入框：

```powershell
adb shell settings put global auto_time ${自动设置时间}
```

使用 `${标题:默认值}` 提供可修改的默认值：

```powershell
adb shell cmd alarm set-time ${时间戳:1786356497528}
```

使用 `${标题:选项文字=实际值|选项文字=实际值}` 创建选择框：

```powershell
adb shell settings put system show_touches ${触摸点显示:开启=1|关闭=0}
```

使用 `${标题@file}` 创建带文件选择按钮的路径输入框，也可以通过
`${标题@file:默认路径}` 指定默认路径。点击文件按钮时，如果当前输入框中已有路径，
文件管理器会从该路径所在目录打开：

```powershell
adb install "${APK安装包@file:C:\Downloads\example.apk}"
```

使用 `${标题@dir}` 创建文件夹选择参数，或用 `${标题@dir:默认路径}` 设置默认文件夹。
点击输入框右侧的文件夹图标打开系统文件夹选择器：当前路径是文件夹时从该目录打开，
是文件时从所在目录打开；也可以直接输入或拖入文件夹路径。取消选择时保留原值。

```powershell
Get-ChildItem "${日志目录@dir:C:\Logs}"
```

| 参数写法 | 选择对象 | 支持默认路径 |
| --- | --- | --- |
| `${文件@file}` | 已有文件 | `${文件@file:C:\Logs\app.log}` |
| `${目录@dir}` | 文件夹 | `${目录@dir:C:\Logs}` |

文件和文件夹路径仍按普通文本替换，路径可能包含空格时需按照脚本语言规则自行添加引号。

脚本需要多次使用同一参数，或需要分开内部变量名与界面标题时，可以在脚本开头声明 `Var`：

```powershell
Var timestampMs = ${时间戳:1786356497528}

Write-Host "即将设置 Android 设备时间"
adb shell cmd alarm set-time ${timestampMs}
```

`Var` 声明行只用于参数元数据，不会交给脚本解释器执行，关键字不区分大小写，`var logs=${日志目录@dir:C:\Logs}` 也有效。文件、文件夹参数也支持这种声明方式，例如 `Var logs = ${日志目录@dir:C:\Logs}`，脚本正文中使用 `${logs}` 引用。旧版脚本中的 `pVal` 声明仍可继续使用，但新脚本统一推荐使用 `Var`。

Python 字符串中的占位符需要自行添加引号：

```python
keyword = "${搜索关键词:Android 工具}"
count = int("${数量:3}")
print(keyword, count * 2)
```

占位符是在执行前进行文本替换。处理不可信内容、路径、引号和特殊字符时，应使用对应脚本语言的安全转义方式。

### 将当前输入设为默认值

自定义脚本详情页和预设命令参数页的文本参数框提供保存图标，鼠标悬停显示“设为默认值”。适用于普通文本、密码、数字、文件路径、文件夹路径和多行文本参数；下拉选项、单选按钮组和复选框不使用该按钮。数字默认值保存前也会校验类型。

1. 在参数框中输入内容，或通过文件、文件夹选择器填入路径。
2. 点击该输入框右侧的保存图标；文件、文件夹参数的保存按钮位于选择按钮左侧，多行文本的按钮位于右上角。
3. 当前内容立即保存为这个参数的默认值，重新选择脚本或重启应用后仍会保留。

空输入也可以保存，用于清空原默认值。保存一个参数不会清空其他输入框中正在编辑的内容。脚本运行期间保存按钮不可用。

默认值保存在本地工具配置中；预设工具使用本地覆盖配置，不修改内置文件。对于可编辑脚本，能通过占位符语法表示的值还会同步写回脚本模板；多行或包含花括号等不能直接写入占位符的内容保存在参数配置中。

### 分享、导入与导出

分享单个脚本时，在右侧详情区点击“分享”，应用会将带格式标识和版本号的脚本 JSON 写入剪贴板。分享内容不携带参数默认值：参数配置中的默认值和脚本占位符中的默认内容都会移除，包含 `Var` / `pVal` 声明及文件、文件夹参数；参数名称、类型和下拉选项保留。本地脚本及其默认值不变，接收方需自行填写参数。设置中的批量导出仍用于完整备份，不受此规则影响。

接收方点击自定义页面的“导入”按钮即可读取：

- 脚本 ID 不存在时追加到当前列表；
- 相同自定义脚本 ID 已存在时询问是否替换；
- 与内置功能 ID 冲突、格式无效或使用内部执行器的内容会被拒绝。

在“设置 → 脚本目录”中可以批量迁移：

1. “导出脚本”在系统文档目录创建包含 `tools` 和 `scripts` 的时间戳目录。
2. “导入脚本”选择之前导出的目录。
3. 导入前自动备份现有脚本，再将导入内容合并；同路径文件使用导入版本，其他本地脚本保留。

批量迁移只处理脚本相关文件，不覆盖外观、更新、设备选择、Jira 飞书方案等应用设置。

## Windows 插件管理

在“设置 → 插件”中可为 Python、Android 工具（ADB + scrcpy）和 PowerShell 选择“应用管理”或“本地环境”。完整版默认附带三套运行时；纯净版不附带运行时，可按需安装。安装和检查插件更新访问官方 NuGet 或 GitHub，更新由用户手动执行。

选择本地环境后，填写或浏览选择 `python.exe`（CPython 3.11 及以上，支持虚拟环境）、`pwsh.exe`（PowerShell 7 及以上）或 `adb.exe`，检测成功后保存。Android 环境可额外指定完整 scrcpy 发行包中的 `scrcpy.exe`，供投屏和录屏使用；只指定 ADB 也可使用设备扫描和 ADB 命令。本地模式隐藏并拒绝插件更新、修复、卸载等操作，由用户自行维护外部环境。

应用管理的插件保存在用户数据目录 `plugins` 中，不修改系统环境。单独更新 Python 插件时会迁移已有依赖，验证通过再启用，失败保留旧环境。运行期间不能切换环境或更新、卸载相关插件；ADB 后台服务仍在运行时，可先点击“停止设备服务”。

**安装或 OTA 升级完整版时，按安装包中的版本检查应用管理的运行时**：版本相同且文件完整则保留现有环境，缺失或已卸载的运行时会补齐。Python 版本变化时，先导出原专用环境的依赖，在新环境中自动安装并执行依赖检查；验证成功后才切换并清理旧目录，失败则保留旧环境供继续使用和重试。依赖迁移可能需要联网。pwsh、ADB/scrcpy 也只在版本变化或运行时不完整时替换。用户指定的外部环境、所选路径、脚本、配置和输出均保留。纯净版升级不预置或替换运行时。

Windows 本地构建：`packaging/build.ps1 -Edition Both`（默认），也可选择 `Bundled` 或 `Clean`。完整版构建校验并预置三套运行时，纯净版构建无需它们的发行包。macOS 打包方式保持不变。

运行时发行包不提交到源码仓库，只保留固定版本、官方下载地址、SHA-256 和许可证。Windows 构建缺少 Python、scrcpy/ADB 或 PowerShell 包时会自动下载并校验；macOS 构建同样按架构清单下载。GitHub Workflow 按系统、架构和清单内容缓存原始发行包，每次构建仍校验 SHA-256，缓存缺失不会影响正常下载。下载只发生在构建阶段，完整版安装后仍可离线使用三套运行时。

## Python 环境与依赖

## 内置终端

“终端”入口始终显示。Windows 首次进入时会提示下载、校验并安装应用专用 PowerShell 7；macOS 使用用户系统 Shell。环境准备完成后会直接进入终端页面。

终端支持多个标签页，每个标签页拥有独立 Shell 会话、当前目录和输出记录。切换页面不会结束会话；关闭标签页会停止对应会话，始终至少保留一个标签页。“重启会话”只重启当前标签页。

终端会把应用专属 Python、pip 和内置 ADB 加入环境，可直接执行：

```text

pip list
pip install requests

```

快捷键和鼠标操作：

- `Ctrl+V`：粘贴剪贴板内容；
- `Ctrl+X`：存在选区时复制并清除选区；
- `Ctrl+L`：清屏；
- `Ctrl+Shift+C/V/X`、`Ctrl+Insert`、`Shift+Insert`：兼容复制、粘贴和剪切；

进入“设置 → 外观”可以选择跟随系统、浅色或深色模式，修改会立即生效并在下次启动时保留，不会影响脚本、设备或推送方案。

## 应用更新

发布版启动后按设置的频率异步检查 GitHub Release，也可以在“设置 → 关于”手动检查。每天模式在每个本地自然日最多自动检查一次；每周模式在每个周一开始的自然周最多自动检查一次；选择“从不”会关闭自动检查。无论检查成功或失败，同一周期内都不会重复自动请求。

- 正式渠道读取 GitHub 最新正式 Release；
- 开启“接收测试版本”后，从最近 5 个正式版或 prerelease 中按版本号选择最高版本；
- 发现更新时在弹窗中直接显示该 Release 的 Markdown Release Notes；
- 弹窗高度随说明内容调整，最长内容使用滚动区域；
- 可以下次提醒、跳过当前版本、立即下载、取消下载、稍后安装或安装并重启；选择“稍后安装”后，下次启动会先校验并自动应用已下载的更新；
- 下载文件会校验大小以及 GitHub digest 或配套 SHA-256。

Windows 主推完整版 `PopTools-Setup.exe`（附带 Python、Android 工具、PowerShell），同时提供纯净版 `PopTools-Clean-Setup.exe`（不附带可选插件）。两者都能独立启动，应用自身必需的 Python 库不属于可卸载插件。自动更新保持当前发行类型；完整版安装或升级按版本更新应用管理的运行时；纯净版升级保留已有插件，外部本地环境始终保留。macOS 根据架构使用 `PopTools-macos-arm64.zip` 或 `PopTools-macos-x64.zip`。

Windows Release 还必须保留 `PopTools.exe` 和 `PopTools.exe.sha256`，用于兼容 1.1.0 及以前具备 OTA 功能的客户端。它是内嵌同次构建集成版安装包的独立升级程序，不能用改名的安装包或新版目录式应用入口代替。旧版下载后会自动迁移到原目录、保留用户数据和插件，并启动新版；后续更新恢复使用正常安装包，无需手动覆盖安装或经过中间版本。

迁移失败时会显示错误，安装包、`migration.log` 和 Inno Setup 的 `setup.log` 保存在 `%LOCALAPPDATA%\PopTools\updates\legacy-ota-*`（设置 `POPTOOLS_DATA_DIR` 时位于该目录下的 `updates`）。辅助进程输出记录在 `helper.log`，启动准备失败时记录 `bridge-error.txt`。关闭占用进程后，可以在失败目录中通过 PowerShell 运行 `apply.ps1` 重试。成功后自动清理安装包和辅助脚本，保留 `helper.log` 供排查。兼容能力从包含这些资产的新 Release 开始生效；正式渠道需发布正式 Release 才可发现更新。

## 常见问题

- **找不到 Android 设备**：确认 USB 调试已开启并授权，重新连接后等待设备列表刷新。
- **Bash 无法运行**：Windows 需要可用的 Bash 环境，例如 Git Bash；macOS 使用 `/bin/bash`。
- **Python 提示缺少依赖**：使用 Python Doctor 安装，或在内置终端中执行 `pip install`。
- **终端无法进入**：Windows 首次使用需要完成 PowerShell 7 插件安装；安装失败时检查网络后重试。
- **Jira 或飞书操作失败**：检查地址、凭据、JQL、机器人安全设置和当前网络。
- **定时推送没有执行**：确认方案启用定时、调度器已经启动，并保持应用进程运行。
- **关闭窗口后程序仍在运行**：应用已隐藏到系统托盘，可从托盘菜单完全退出。
- **运行任务达到上限**：根据提示停止最早启动的普通任务后再运行新任务。
- **检查不到 prerelease**：开启“接收测试版本”后重新检查。

## 开发与构建

悬浮窗使用分层组件：`FloatingLauncher.qml` 管理窗口、置顶和展开收起；`CustomScriptList.qml` 共用搜索、筛选、排序并按主题加载展示组件；`StandardScriptList.qml` 显示普通列表，`DecadeScriptDeck.qml` 管理卡包叠放及抽出、归还的位置与遮挡。两种展示组件通过统一的激活、归还接口与外壳交互，共用 `ScriptCollectionView.qml` 的滚动和键盘导航。`ScriptCardStore.qml` 独立持有卡面对象，生命周期不依赖列表项或主题组件，切换主题时可继续复用正在飞行或已抽出的卡面。

快速点击时，卡包同步保留卡面以合并重复请求，窗口创建在鼠标事件结束后派发，不等待其他卡牌动画。列表关闭离屏委托缓存，避免快速移除行时取消仍在异步创建的委托；首帧通知也不直接修改源列表模型。窗口关闭会取消尚未完成的表单加载。排查闪退时可结合用户数据目录下的 `logs/native-faults.log`、`logs/app.log` 和 Windows 应用程序错误事件；应用日志中的卡片请求只记录脚本 ID 和卡片数，不记录命令或参数内容。

项目使用 Python 3.11 开发，依赖 PySide6、Pydantic、Requests、platformdirs、psutil 和 pypinyin。创建开发环境：

```powershell
uv venv --python 3.11 .venv
.\.venv\Scripts\python.exe -m pip install --no-build-isolation -e ".[dev]"
.\.venv\Scripts\python.exe -m poptools
```

运行测试与静态检查：

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\ruff.exe check src tests
```

视频性能可用同一段素材在目标电脑上复测（`--ui` 会打开实际播放器窗口并模拟时间轴拖动）：

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_video_preview.py "sample.mp4" --ui --output build/video-benchmark.json
```

报告分别记录源视频解码、预览缓存读取、界面拖动及松手恢复原生画面的耗时。界面测量在目标图像就绪后再等待两次窗口绘制提交，作为保守延迟上界，不代表屏幕像素实际发光时间。拖动部分使用准备完成的预览，首次生成耗时另行记录；复用缓存时，该项仅为打开已有缓存的耗时。大文件或长片只准备抽样位置附近的预览，无需生成整部电影；报告中的 `proxy_mode` 区分整段和按需缓存。保留原文件以便设备间比较。可加 `--cpu-count 1` 限制进程 CPU，但这不能替代不同设备上的实测。脚本只写指定报告和缓存目录，不读取应用的播放列表。

连续交互压力测试使用独立播放列表和缓存，默认以约 60 次/秒发送鼠标移动，交替执行全片随机拖动、局部放大拖动，以及切换文件、画质、播放状态、列表与窗口大小：

```powershell
.\.venv\Scripts\python.exe scripts/stress_video_preview.py "movie.mkv" --alternate "short.mp4" --seconds 60 --output build/video-stress.json
```

可加 `--cpu-count 2` 测试 CPU 受限情况。报告包含主画面数据更新间隔、界面心跳间隔、进程内存、操作耗时和退出后残留工作线程；校验最终定位、拖动时弹窗隐藏、播放器布局稳定与 QML 错误。脚本默认使用 Qt `basic` 渲染循环，数据反映解码与界面事件处理，不代表屏幕实际呈现帧率。播放测试音量为 10%，素材和实际应用的播放列表不作修改。

完整主窗口的长时间混合压力测试按实际墙钟时间运行，默认持续一小时：

```powershell
.\.venv\Scripts\python.exe scripts/stress_application.py --seconds 3600 --tools 500 --video "movie.mkv" --alternate "short.mp4" --output build/app-soak.json
```

每分钟循环切换脚本、设置、手册、终端、调色盘、Android 空状态、视频和更新弹窗，执行无害的本地 Python 脚本，反复创建和关闭真实终端会话，并测试视频拖动、播放列表、文件切换、画质、倍速与窗口缩放。测试配置和脚本保存在报告旁的 `*-session` 新目录；视频只读，播放音量为零。输出包含逐分钟内存、线程、句柄和子进程数量，界面心跳、各操作耗时、截图、错误及退出后的残留子进程。加 `--trace-actions` 可记录每一步完成后的资源数据。再次运行需更换报告名，以免复用旧测试数据。

该脚本默认采用离屏软件渲染，能够检查界面布局和事件响应，不能测量桌面合成器帧率。真实 Android 操作、Jira/飞书网络请求、插件下载安装和应用升级需在专用设备或测试环境中另测；现有 pytest 覆盖其本地逻辑和模拟失败路径。Windows 原生窗口、桌面输入及 GPU 效果测试应在可交互桌面运行，不能以离屏结果替代。

卡牌原生窗口回归可单独运行（仅使用临时数据和合成脚本，不执行脚本）：

```powershell
.\.venv\Scripts\python.exe tests/card_motion_probe.py build/card-motion-stress.json decade
```

末尾主题也可指定 `light` 或 `dark`。测试由独立父进程监护，超过 90 秒会结束本次测试进程树，避免无响应窗口留在桌面。帧信号必须排队回到界面线程采样，不能从渲染线程同步调用 Python；否则模拟点击等待渲染时可能与 Python 锁互相等待。报告中的帧间隔是界面线程收到通知的间隔，并非 GPU 呈现时间。

Windows 构建：

需要安装 Visual Studio / Build Tools 的“使用 C++ 的桌面开发”工作负载（含 MSVC 和 Windows SDK）。脚本会自动识别安装位置（包括 Insiders / 预览版），加载 x64 编译环境，使用 NMake 构建，无需手动打开开发者终端。CMake 已包含在开发依赖中；直接运行原生构建脚本时，缺少的 CMake 也会自动安装到项目 `.venv`。未设置 `QT_ROOT_DIR` / `Qt6_DIR` 且找不到 qmake 时，脚本会自动下载 Qt C++ SDK 到 `build/qt-sdk`，首次构建需要联网。

```powershell
.\packaging\build.ps1
```

macOS 构建：

```bash
uv venv --python 3.11 .venv
./packaging/build.sh
```

版本以 `pyproject.toml` 为来源。GitHub Release 使用 `vYYYY-MM-DD_x.x.x` 标签，并构建 Windows x64、macOS arm64 和 macOS x64 资产。
