客户端渲染 View，服务端只持有 Surface。所有状态变化都是「改弹簧目标」。

Surface 树（容器子树由中台完全管理）

Window [expandedW+2·阴影, maxH+顶边距+阴影, 顶部居中, 永不 relayout]
 └─ SurfaceView [zOrderOnTop, 根 SC]
   └─ islandContainer [position / crop / cornerRadius / shadow]
     ├─ border [color layer · 1dp 半透明描边]
     ├─ bg [color layer · 纯黑]
     ├─ content_COMPACT [客户端 SC · reparent]
     └─ content_EXPANDED [客户端 SC · reparent]

客户端死亡 → 内容层变空，bg 仍在，岛平滑消失，不闪屏。窗口创建后永不 relayout，所有形变靠 SurfaceControl.Transaction 的 crop / position / matrix / alpha / cornerRadius。

04

队列与仲裁

只有客户端 show/hide 能改队列；服务端不管控内容。

  1. 成员只因 show 加入、hide / 连接断开 移出。
  2. 屏幕显示 argmax(priority)；同级先入队者先显示，后到的排队不抢占。
  3. 高优先级到来：立即成为显示项，原项 留在队列，presence 变 QUEUED。
  4. 显示项 hide：次高补位；队列空则岛消失。
  5. 对已入队条目重复 show：幂等更新（优先级 / 期望状态 / 内容），入队序号不变。
  6. 被抢占者保留入队序号，补位时排在后来同级者之前。
  7. 补位上屏时期望状态上限压到 COMPACT，避免旧内容突然弹出大面板。
fun top(): IslandItem? = entries.maxWithOrNull(
    compareBy<IslandItem> { it.priority }
        .thenByDescending { it.enqSeq })

仲裁行为表

show · 队列空 → 立即显示
show · 优先级高 → 抢占 · 原项 QUEUED
show · 优先级低 → 入队 · 屏幕不变
hide 当前项 → 次高补位
hide 排队项 → 静默出队
setDesiredState 当前 → 立即执行
setDesiredState 排队 → 仅记录
进程死亡 → 该连接全出队
